## Features implemented
- Strict versioned lesson/step contract: default three, maximum five ordered steps; one to three existing Day 4 actions per step; server UUID and stable step-N identifiers; objectives, expected behavior, observation questions, concepts, explanations and explicit completion criterion.
- `/api/ai/generate-lesson`: verifies Context v1, supplies typed capabilities, makes one bounded completion, validates every operation sequentially, computes authoritative before/after and physics on temporary state, returns lesson or unsupported capability. No automatic execution.
- `/api/ai/evaluate-observation`: independently reconstructs the full lesson, verifies current parameters/physics against the chosen step, returns structured assessment, feedback, explanation, optional hint, suggested action and separate authoritative physics. Incorrect/incomplete/vague assessments require retry. Only correct + continue unlocks progression; no mastery certification.
- Explicit browser learning state machine, including generating, ready, awaiting_confirmation, experimenting, awaiting_observation, evaluating, feedback, completed, cancelled and error/recovery. One active lesson in app memory, answer retry, previous-step restoration/restart with new previews, explicit exit.
- Shared Day 4 preview, action validation, snapshot/revision checks and atomic Zustand commit. Entire step validates before any mutation. Manual edits, preset changes, resets and ABA changes invalidate previews/observations; stale asynchronous results cannot advance progress. Reconstructing an earlier step shows actual-current versus validated target parameters and requires confirmation.
- Responsive Free Experiment / AI Tutor / Guided Learning modes using the existing Canvas and controls. Standalone tutoring, presets, authored lessons and comparison remain available.
- Shared en/zh-CN preference for new tutor/proposal/lesson requests. Natural-language fields are script-checked, including rejection of untranslated English prose in Chinese fields while preserving existing parameter identifiers/SI symbols. Language mismatches fail clearly without hidden translations or retry loops; older standalone API callers may omit preference.

## Architecture decisions
Existing deterministic engines remain authoritative. Each step inherits the last step's final state; mass/other parameters are retained unless explicitly changed by a validated action. Duplicate writes, invalid intermediate values, preset-after-write and reset mixed with other actions are rejected. The frontend reconstructs the full chain before accepting a plan or confirming restoration. Day 4 and Day 5 share snapshot logic, action operations, preview rendering and atomic commit shape, with no new simulation implementation or unrestricted tool mechanism.

Lesson completions are fixed at 3500 output tokens, with 32 KiB upstream and 64 KiB request limits; existing explanation/feedback defaults stay at 1500 tokens. All AI routes share per-process admission, timeout, origin/loopback and safe error handling. Prompt/credential echo is rejected. Language fallback is a safe explicit error, not automatic paid correction. State-machine transitions prevent next-step progression for stale contexts or a retry recommendation, even with a correct assessment.

Browser persistence is deliberately deferred: safe restore would need versioned plan/progress/answers/context validation, pending-state normalization and explicit restore confirmation. One session survives UI mode switches in memory; refresh discards it. No credentials, prompts, hidden provider data, answers or snapshots are written to browser storage. No database was added.

## Known limitations
Local-only MVP and per-process concurrency, not public authentication/global quota control. In-memory sessions are lost on refresh. Browser language checks use scripts/word patterns, not semantic proof or complete language identification; unusual quoted terms may cause a conservative failure. Generated narratives can contain typos or mistaken intent; physics values remain deterministic and review stays mandatory. Feedback is advisory, not certified grading/mastery. One experiment type and at most five steps/three actions per step; no arbitrary execution. Backend lesson IDs are correlation values, not signed authorization or persistent records. No long-duration memory stress test was claimed; request abort/subscription cleanup and stale asynchronous work are covered by tests.
