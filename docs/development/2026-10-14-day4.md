### Architecture and validation decisions
Four operations only: set_parameter, scale_parameter, select_preset, reset_simulation; exact existing parameter paths, SI values, factor (0,10], no extra/unknown fields or confirmation overrides. Incoming Context v1 is verified before planning; provider output is untrusted. The backend computes before/after physics on copies with existing canonical equations. The frontend validates schema, identity, parameters and preview using its own existing engine. A single synchronous Zustand setter rechecks the request revision/current parameters and applies a paused, t=0 update; baseline remains untouched and the comparison panel reacts normally. Every parameter/preset/reset operation increments the revision, preventing stale and edit-then-revert acceptance. Animation time and lesson navigation alone do not invalidate parameter proposals, because confirmation always starts a new t=0 experiment. Snapshot IDs are correlation metadata, not authentication. A deterministic axis guard supplements model clarification for ambiguous field instructions. No backend state mutation or automatic execution exists.
